# 👾 CWE-362 — Race Condition

> **Two jobs reached for the same thing at the same time.** A piece of code needs
> to access a shared resource **alone** for a short while. But there is a gap in
> time, and in that gap someone else can touch the same resource.

| | |
|---|---|
| **Official name** | Concurrent Execution using Shared Resource with Improper Synchronization ('Race Condition') |
| **Abstraction level** | *Class* |
| **Parent** | CWE-662 — Improper Synchronization |
| **Its child in the catalogue** | [367](./cwe_367.md) — TOCTOU |

---

## There Is Always a Gap

A job looks like "a single move" but rarely is one:

```
   read   →   decide   →   write
       ↑             ↑
     here          here      someone else can step in
```

That gap is called the **race window**. However narrow the window is, it is not
zero — and as long as it is not zero, it is possible for someone to land in it.

> 🔑 A race condition is **not a mistake but an omission**: the guarantee "right
> now only I am here" was never established while accessing the shared resource.
> The code can be correct on every line; what is wrong is not accounting for what
> can happen between the lines.

And in practice the most annoying part: **it works most of the time.** As long
as nobody lands in the window, everything looks fine. The bug only shows up
under load, on another machine, or when someone lands in it on purpose.

---

## Where the Software Side Meets the Hardware Side

The interesting thing about this class in your catalogue is that **it brings two
separate series together.**

| CWE | Where | What |
|---|---|---|
| [**367**](./cwe_367.md) — TOCTOU | Leviathan · binary exploitation | The file changed between the check and the use ✓ *you have it* |
| **1298** — Hardware Logic Contains Race Conditions | The clock unit (*on the way*) | Signals travelled at different speeds, the circuit was left unstable |

One lives in the file system, the other on a wire. But the definition covers
both: **a shared resource, concurrent access without synchronisation.**

> 💡 Remember this when you reach the clock unit: latches and race conditions are
> TOCTOU's sibling in hardware. "The signal was delayed on the way" and "the file
> changed in between" are two scales of the same sentence.

Its other children also show how common the pattern is:

- **CWE-366** — Race Condition within a Thread
- **CWE-364** — Signal Handler Race Condition: the signal handler touches data
  used by the code it interrupted
- **CWE-368** — Context Switching Race Condition
- **CWE-689** — Permission Race Condition During Resource Copy: while the copy is
  running, the permissions have not settled yet
- **CWE-421** — Alternate Channel: access through a side channel while the main
  channel is protected
- **CWE-1223** — Write-Once Attributes: a field that may be written once gets
  written twice

---

## Narrowing the Gap Is Not a Fix

A common wrong defence: shortening the time between the check and the use.

That does **not close** the hole — it only narrows the window. The attacker can
repeat the attempt a million times; you only need to miss once.
[367's page](./cwe_367.md) explains this point in detail.

The right defence is **removing the gap**:

```
  wrong:    check  →  (narrow gap)  →  use
  right:    do it in a single indivisible operation   or   lock
```

---

## Why It Has Its Own Page

You do not label a real vulnerability with 362; the most concrete level is
chosen ([the hierarchy rule](./README.md#the-hierarchy-between-cwes)).

The reason it has a page is the bridge above: [367](./cwe_367.md) in your
catalogue looks like a file-system problem, while **1298** on the roadmap looks
like a hardware problem. The kinship between them only becomes visible from the
umbrella — and once it does, the reflex you learned in Leviathan also helps you
when you look at a clock circuit.

---

## How to Prevent It

- **Use an indivisible operation** (*atomic*). If there are calls that do the
  check and the action in a single move, prefer them — the gap is never born.
- **Lock.** Establish the "right now only I am here" guarantee explicitly with
  mutual exclusion (a mutex, a file lock).
- **Reduce sharing.** The most solid defence is not sharing the resource at all:
  a private directory, a separate copy per process, a temporary file nobody else
  shares.
- **Work with a handle, not a name.** Open once, then always use that handle (a
  defence shared with [706](./cwe_706.md)).
- **Do not take "it works most of the time" as proof.** Race conditions escape
  testing; their absence is guaranteed by design, not by tests.
